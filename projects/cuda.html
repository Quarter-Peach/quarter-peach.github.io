CUDA / ENGINEERING · 从算子到模型验证

BERT · CUDA 算子调研与自实现

从 BERT 调用追踪到 ATen 分发，针对特定输入编写并验证 Softmax CUDA Kernel。

CONTEXT

并行与分布式程序设计项目

TIME / SETTING

RTX 4090 / PyTorch 2.1.0

MY ROLE

Softmax 自实现与验证

从一次 BERT 推理，一路追到底层 Kernel

这个项目以 bert-base-uncased 为对象，研究 PyTorch 算子如何被调度到 CUDA 内核，并对 Softmax、Addmm、LayerNorm 开展小组调研与实现。

我的贡献：负责整体算子调研、CUDA Runtime API 调用分析，以及 Softmax 的源码追踪、自定义 CUDA Kernel、正确性验证与性能测试。Addmm 和 LayerNorm 自实现由组内其他成员负责。

我的技术路线

01定位热点用 torch_tb_profiler 分析算子耗时与时间线。
02追踪分发沿 native_functions.yaml、ATen 和 CUDA 实现逐层查找。
03定制 Softmax针对末维 128、FP32 推理场景优化内核和分发。
04双层验证分别检查算子数值误差与 BERT 输出一致性。

为观察被融合注意力隐藏的 Softmax，实验切换到 eager attention；进一步追踪到 PersistentSoftmax 的特化路径，并通过环境变量开关对照原生与自定义实现。

定制 Kernel 与精度取舍

  • Warp-per-row：让一个 Warp 处理一行 128 个元素，以固定映射减少动态判断。
  • 向量化访存与寄存器计算：采用 float4 读取、Warp Shuffle 规约，并融合求和、归一化与写回。
  • 精度回归：在版本迭代中比较 fast math 与标准数学函数，检查局部数值误差及最终模型输出。

最终测试包含独立 Softmax 基准、与 CPU 参考结果的数值对比，以及替换算子后 BERT 推理输出的比较。
